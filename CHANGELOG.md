# Changelog

## Unreleased
- Fixed the managed host/review integration so **approval can no longer precede its visible specification/result summary**: the exact native approval question now embeds the concise Decision Capsule before the choices; normal approval no longer generates or offers Review Cockpit, keeping canonical required visuals inline and the complete Review Bundle available as Review Details. SpecRail now declares and installs official `@dietrichgebert/ponytail@4.8.4` as a runtime dependency, including its official skills/extension; a Pi state bridge materializes Ponytail's official default `full` mode when no explicit mode record exists while preserving explicit `off`/`lite`/`ultra` choices so mutation still fails closed. Managed installation now exposes deterministic `specrail install --pi` / `--no-pi`, asks only in an interactive terminal when neither flag is supplied, skips Pi by default when non-interactive, and guarantees `--no-pi` leaves existing Pi settings/instructions untouched. Installed-launcher regression coverage exercises those flags through the real `~/.local/bin/specrail` dispatcher.
- Added **explicit entry and mutation governance** for every new repository-delivery work item: the host now asks for `SpecRail`, `Directo`, or `Directo + verificar` (plus free-text/Other) before workflow state or mutation unless an explicit route prefix/continuation already resolves it; process route remains separate from `micro`/`light`/`standard`/`rigorous`. Direct routes may persist only safe Pi session routing metadata and do not create repository-local SpecRail task/workflow state merely to remember the bypass. Production-code writes now require runtime-backed No-Assumption provenance, official `@dietrichgebert/ponytail` in literal `full` mode rechecked at mutation time, and a fingerprint-bound official post-mutation Ponytail review. Direct + Verify uses a fail-closed read-only verifier over Git-visible tracked/non-ignored-untracked content, fingerprints from the Git root even from nested CWDs, hashes symlinks without following external targets, and rejects shell/interpreter wrappers. Approval output is Decision Capsule-first while the complete authoritative Review Bundle remains attached as Review Details instead of being dumped inline by default.
- Completed **first-class Pi coding-agent compatibility hardening** without forking the workflow: npm metadata exposes Pi `extensions` + `skills`; native `pi install` and managed `specrail install --pi` load the same Pi Package contract, while managed installation can explicitly opt out with `--no-pi`; the managed Pi route registers `~/.ai-flow` as a local package instead of copying a dependency-fragile loose extension; `specrail_cli` executes its Bash dispatcher directly (fixing Linux `/bin/sh`/`dash` failures), throws on non-zero/killed subprocesses so Pi marks real tool errors, and is sequential to protect deterministic state under Pi's parallel tool batches; native human gates are also sequential; `specrail_skill` loads the packaged `ai-flow` orchestrator and deterministic specialist contracts without `.agents` path assumptions; Taste accepts Pi as a supported host and Pi skill roots; fresh handoffs use replacement-session `withSession`; CodeGraph failures fail closed; and runtime tests execute the real bundled dispatcher plus activation, session, UI, specialist, installer, error, and handoff contracts. Model/thinking remain host-owned; normal visual review uses the chat-first Decision Capsule, canonical inline evidence, and Review Details, while Review Cockpit is manual legacy only; independent subagents remain serial until truthfully attested.
- Completed **incremental-governance hardening** with `REV-*` schema v3: revision routing no longer depends on classification mappings. SpecRail seals a workspace baseline when a bounded revision starts, derives provisional semantic signals from request/files/explicit context, then recomputes invalidation and the minimum validation route from the files actually changed by Builder. Classification is descriptive only, arbitrary future labels need no router changes, baseline integrity is checked, and material architecture/data/security/product/contract deltas discovered after implementation fail closed before the fast path can continue. Schema-v1/v2 revision records remain readable and integrity-compatible.
- Added the declarative artifact dependency graph and universal post-approval revision routing: bounded revisions can start from Builder/review/QA/Audience/Final/pre-merge Delivery, while user-waivable steps derive from a single workflow-gate registry (including design and technical architecture) instead of a duplicated override target list.
- Added **User Governance Overrides** so an explicit current-turn user instruction can close a task or waive a named review/QA/evidence/delivery gate exactly once without entering a repeated fail-closed loop. Overrides are immutable/auditable, require explicit `--user-authorized`, are never available to autonomy by default, mark readiness gates as satisfied-by-override rather than falsely verified, cancel active revisions on terminal closure, and preserve unmerged worktrees instead of fabricating delivery.
- Added the **Incremental Revision Loop** for bounded final-review refinements: immutable `REV-*` records keep iteration inside the same task, use a compact Revision Delta Capsule, bypass unnecessary Technical Review/full QA/Target Audience/Product Owner replay, preserve unaffected governed artifacts/evidence, and do not consume repair budget. Revisions are explicitly implement-first—no speculative new test planning before the requested delta stabilizes; cheap direct validation happens after implementation and permanent regression coverage is decided afterwards when valuable. Builder passes now advance integrity-bound `GEN-*` implementation generations, affected acceptance/evidence must prove the current generation, and material architecture/data/security/product-flow/breaking-contract feedback fails closed to Amendment/full review.
- Added proportional **Control Profiles** (`micro`, `light`, `standard`, `rigorous`) driven by governed Need/Scope/Acceptance Criteria/UI Target, with conservative escalation for behavior, responsive/layout, shared design tokens, redesign, auth/security/data/API/migration/performance/concurrency, and automatic omission of Product Owner/Target Audience/durable-learning passes for proven micro/light work.
- Added explicit **`SpecRail Fast:`** for an ultra-light governed micro/light path and **`Sin SpecRail:` / `No SpecRail:`** as a one-request total bypass. Fast auto-escalates back to the normal 0.10 workflow when refinement reveals material risk and still preserves Scope Guard, spec/AC integrity, real evidence, Acceptance Coverage, presentation acknowledgment, and final approval.
- Added a transparent persistent TypeScript CLI runtime using the same argv parser for all normal commands, preserving `next`, `readiness`, and `interaction` as separate contracts while removing repeated Node/module cold starts; added stale-lock recovery, build-generation sockets, per-call CWD/session environment, concurrency serialization, and idle shutdown.
- Reworked CodeGraph lifecycle management: cached binary-contract probes, bounded health TTL, watcher/catch-up as the normal freshness path, incremental `sync` only for recovery, metrics with bounded retention, and no automatic full `index --force` outside explicit Doctor repair.
- Added Codex fresh-chat handoff deep links that target the current workspace and prefill `Continue TASK-####` while preserving the required user send/phase-entry boundary.
- Added **Multi-Agent Concurrency** with dependency-aware waves, integrity-sealed global plans, reservation + task-lease authority for every lane, project-wide `maxParallel` enforcement across parent plans, binding scheduler ownership of planned tasks, reservation-specific sessions renewed per role dispatch, explicit `concurrency heartbeat` for long-running lanes, fail-closed stale-reservation holding so lease expiry never authorizes silent redispatch, human-gate authority yielding, external-dependency/depth checks, current Scope Guard validation, conservative write-conflict serialization, isolated Builder worktrees, transactional rollback for synchronous partial wave preparation, PID-aware scheduler locks, explicit release/cancel recovery including corrupt-plan force recovery without trusting tampered payloads, parent-gate precedence, deterministic `next` routing, integrity-sealed host parallel-capability attestations, and deterministic `serial-fallback` when real host parallelism is not attested.
- Added a clean-room validation record for the 0.9.1 Autonomy + Product Intelligence + Multi-Agent Concurrency integration: 346/346 tests, release checks, packaging, interprocess scheduler races, installed E2E, and byte-identical source-tree comparison after applying the patch to the current 0.9.1 baseline.

- Sealed specification review state before computing presentation acknowledgments: legacy QA Mission/quality/governance normalization and Scope Guard baselines now happen before review, repeated review preparation is idempotent, and exact Review Bundle plus canonical visual bytes participate in freshness so approval cannot accept content that changed after presentation.
- Hardened review presentation and phase-boundary UX: canonical visual evidence is `requiredVisible`, local paths are audit-only, and visual approval uses session/digest-bound blocking `present-image` acknowledgments before any native decision can be emitted or accepted. The exact approval question itself includes the Decision Capsule summary before its choices, so hosts cannot render an approval selector without the decision-critical specification/result context. Review Cockpit is no longer generated/opened/offered by normal gates and remains an explicit manual legacy command; Visualize stays optional and never replaces canonical evidence or Review Details. Pending visual Amendments cannot bypass presentation through the CLI, `spec approve` returns the native implementation-boundary choice at top level, and browser QA requires a structural host-browser surface, invocation reference and served target while preserving human verification separately.
- Added **Autonomy Levels** (`guided`, `autonomous`, `headless`) with policy-aware deterministic approvals, Guided Product Owner acknowledgement, automatic mechanically safe implementation/review phase-boundary entry in Autonomous when a stable session is available, `headless-stop` when Headless cannot enter a boundary safely or unresolved user/external judgment remains, and opt-in autonomous local-merge delivery without auto-answering questions/amendments/product trade-offs.
