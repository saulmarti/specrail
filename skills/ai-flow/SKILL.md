# AI Flow
Do not require the user to mention AI Flow, a skill name, a task ID, or a CLI command, and do not expose internal CLI instructions to the user.

## Entry gate and invariants
For every new delivery work item, choose the process route before any SpecRail task, CodeGraph preflight, gate, evidence state, or learning exists. Unless this is explicit `Continue/Resume/Retoma TASK-####` or a route prefix, use native `request_user_input` with `SpecRail`, `Directo`, `Directo + verificar`, and `Other`/free text. Never select a route for the user.
`Sin SpecRail:` / `No SpecRail:` means bypass SpecRail completely **as workflow state only**: no SpecRail CLI, task, CodeGraph preflight, gate, evidence state, or learning. `Directo + verificar:` / `Direct + Verify:` adds the smallest meaningful final verification. `SpecRail Fast:` selects governed SpecRail and uses `--mode fast`. Never infer total bypass from impatience or wording without an explicit route. Process route is independent of `micro/light/standard/rigorous` and Guided/Autonomous/Headless.
For every code-writing route require the official Ponytail capability in literal `full` mode before mutation. Missing/off/lite/imitated Ponytail blocks mutation; never install third-party code silently and never offer a per-work-item bypass. Before a mutation phase completes, run official `ponytail-review`. User requirements, security/privacy, accessibility, data-loss protection, approved scope, acceptance criteria, and evidence outrank minimalism.
Never fill a material unknown with model confidence. Resolve it from explicit active user input, an approved decision, an authoritative repository contract, one unique repository pattern, or current deterministic tool evidence; otherwise ask 2–4 concrete choices, at most one recommendation, plus free-text `Other`. Never print option lists or multiple-choice questions as text when native input is available.

## Host adapters
- **Codex:** use native `request_user_input`; only after SpecRail is selected use the managed/global `specrail` launcher. The current chat model is the Brain. Worker phases launch through packaged `specrail-worker`, which pins Luna/Terra in isolated `codex exec` processes instead of trusting model inheritance. `$visualize` remains optional and host-specific.
- **Pi:** use `specrail_entry_gate`; after SpecRail selection use `specrail_cli`, exact `specrail_host_context`, `specrail_skill`, and `specrail_codegraph`. The current Pi model is the Brain; worker phases launch through `specrail-worker`, which starts isolated Pi runs with explicit `--model`. `/specrail-handoff TASK-####` or `/new` + `Continue TASK-####` remains the fresh-boundary fallback.
- Without an interactive UI, never emulate a process route or human decision in text; stop unless explicit authority already exists.

## Deterministic control
1. Resolve existing work with `ai-flow resolve` by ID, exact title, or unique phrase. Task Markdown is the source of truth. Ambiguity uses the native task selector; never guess or create duplicate intake. Show `TASK-#### — Title`, easy to reference in another chat by ID, title, or descriptive phrase.
2. Let SpecRail own CodeGraph lifecycle. Do not manually run `codegraph init`, `sync`, `status`, or `index` during healthy task routing. Cached contract/health state and active CodeGraph transport are authoritative; full reindex is an explicit Doctor repair only. Fast micro/light may defer project-wide CodeGraph until escalation.
3. Read `next` first. If `specrail next` fails, treat it as a runtime blocker; `readiness` and `why-blocked` are diagnostics and never replace routing authority. Load only the returned specialist: on Pi call `specrail_skill`; on managed Codex read `.agents/skills/<recommendedSkill>/SKILL.md`. Do not rely on automatic mid-turn skill reselection and keep unrelated skills out of context.
3a. `next.intelligence` is authoritative for **Brain/Worker ownership**. `none` means deterministic/human work; `brain` means the current user-selected chat model owns the governed judgment; `worker` means the Brain MUST delegate heavy work through `specrail-worker` when that launcher is available rather than performing the phase itself. The worker order pins `gpt-5.6-luna` first and may try `gpt-5.6-terra` only when the requested model is unavailable. Silent fallback to the Brain model is forbidden. A worker receives a sealed minimal capsule, not chat history, and must return `ESCALATE_TO_BRAIN` instead of deciding product, architecture, public contracts, security/privacy, migrations, governed UX, scope expansion, or consequential user questions.
3b. When `SPEC_RAIL_WORKER=1`, execute only the assigned WorkerOrder/specialist work. Never recurse into `specrail-worker`, spawn another subagent, or call `request_user_input`. On a governed uncertainty return the compact escalation capsule to Brain. After a worker result, the Brain consumes only its compact result/evidence and runs `next` again; do not replay the worker transcript into the main context.
4. Product Owner opinions remain Brain-owned structured advisory judgment. Target Audience simulation may run in a worker, but any product trade-off returns to Brain/human authority. Guided asks for acknowledgement; Autonomous/Headless may advance only mechanically safe decisions.
5. Bounded post-approval feedback defaults to the same task as `REV-*`; do not regenerate the workflow or create a new task. Implement the small revision first, gather invalidated evidence, then decide permanent regression coverage after behavior stabilizes.
6. Explicit close/finish-anyway or skip requests are governance input only for the deterministic close override or a registry-marked waivable workflow step. They never disable Ponytail, security/data-loss protections, or fabricate passed evidence.
7. Use one stable host session token for every human gate and obey `resolve-task-lease`. Respect approved specification hash, immutable QA Mission hash, dependencies, repair budget, evidence gates, and `context.policy`; keep context small.

## Approval and presentation
At a human gate, never construct or paraphrase your own `request_user_input`. Use exact `next.interaction`. When `interaction.tool === "host_actions"`, render the complete `interaction.presentation.markdown` Decision Capsule and execute only returned actions. The complete authoritative Review Bundle remains the `REVIEW-BUNDLE` attachment/Review Details and is available on demand, not dumped into normal chat.
Every `present-image` action must surface canonical evidence in-conversation. Treat Review Cockpit generation and host presentation as different states; never claim generated HTML is open/rendered/visible without a concrete host result. The mandatory fallback remains every `requiredVisible` image plus the `REVIEW-COCKPIT` open action. A stale digest, changed evidence, different session, or tampered acknowledgement forces presentation again.
Normal output is delta-first: at most four short bullets (`%`, implemented, validated, blocker/next) unless the user asks for detail. Blockers, failed ACs, security/data-loss risk, scope violations, and stale/tampered evidence override brevity.

## Phase boundaries and delivery
A phase-boundary native choice is persisted, then the assistant turn ends. On the next turn enter the sealed boundary before implementation/review. Fresh chat is recommended only when runtime says so; same-chat entry is valid after logical authority reset. Brain/Workers does **not** require changing the main-chat model at worker boundaries: the Brain stays selected while the worker launches as its own explicit lower-cost process. Read compiled handoffs; never copy full prior chat.
Done requires final approval and explicit delivery/merge. Use `delivery merge` or externally confirmed delivery; never equate implementation with delivery.

## SpecRail Fast
`SpecRail Fast:` is a shorter governed workflow, not a blind bypass. Micro/light defers project-wide Product Intelligence/CodeGraph and unnecessary agents while preserving exact blast radius, stable ACs, real proof, Scope Guard, Acceptance Coverage, Ponytail full/review, and final approval. If deterministic classification reaches standard/rigorous, the normal 0.10 workflow resumes.

## Frontend and Visualize
Frontend work declares exact `Route → Target → pixel Viewport → Capture`. The primary screenshot must focus the exact task target; page-top/full-page captures are supplementary. Proposals use the installed Taste Skill workflow and Image Gen where applicable; final evidence uses the real app and browser/DevTools.
Serve previews over `http://` or `https://`; never use raw `index.html`, filesystem paths, or `file://`. If `presentation.previewUrl` exists, use it. Canonical generated evidence uses `data:image` / data URI bytes; unresolved local paths produce broken evidence.
Discover exact installed `visualize` skill from the Codex skill catalog. Invoke `$visualize` only from a signed plan when it materially improves review. A valid Visual Comparator keeps exact route/target/viewport/capture context and canonical evidence IDs/hashes. Emit the native `visualize` content reference; generated HTML alone is not presentation.

## Workflow invariants
- Product Specifier removes material ambiguity, writes executable QA Mission, stable `AC-*`, and risk-selected evidence. The deterministic specification linter must pass; approval hashes the governed specification.
- Final approval requires canonical Acceptance Coverage and clean Scope Guard. Governed scope changes use an Amendment; bounded `REV-*` does not rewrite the approved base specification.
- Brain/Worker delegation is different from feature-level Multi-Agent Concurrency. Worker processes never recursively spawn workers. Existing concurrency still governs parallel task lanes and non-overlapping write scopes.
- Repair loops are finite. Required tests/evals/evidence stay risk-selected and deterministic. Store traces/metrics locally only; no external telemetry.
- Environment repair uses `doctor --fix` as a plan and never silently installs Node, Git, CodeGraph, MCP, host plugins, or Ponytail.
